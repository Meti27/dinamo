# Dinamo Orašje

One static page for a burger-and-ice-cream shop in Orašje, Bosnia and
Herzegovina. Its centrepiece is two scroll-linked image sequences, stacked one
after the other: the burger comes apart into its ingredients, holds while they
are labelled, and goes back together; then a scoop of ice cream turns a full
circle in a cone, with its own opening line and its own closing line. Both are
scrubbed frame by frame against the scroll position, not played as video.

## Running it

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # type-checks, then emits a static dist/
npm run preview    # serve the built dist/
npm run frames     # rebuild the burger sequence
npm run icecream    # rebuild the ice cream sequence
```

`dist/` is plain static files — host it anywhere. There is no server, no
database and no router.

## How the sequences work

Both sequences are shot the same way: a subject over a studio backdrop that
never moves. `scripts/matte.py` is the shared technique both build scripts use —
the backdrop is reconstructed (a cubic surface fitted per channel to the pixels
outside a box the subject and its shadow never leave, predicting the backdrop
*behind* it, which a plain median across frames can never recover), then
subtracted for a real alpha channel and a contact shadow. Encoded to AVIF —
`ffmpeg`'s own AVIF muxer drops the alpha plane, so frames go through `avifenc`.

**The burger** (`scripts/build-frames.py`, 30 PNGs) only runs **closed → apart**,
so the way back is the same frames in reverse — where "the burger goes back
together" comes from without a second sequence. Cropping takes it to 19% of the
source area. The script also measures where each labelled ingredient sits, per
frame: these layers never fully separate, so it finds the **waists** in the
burger's outline rather than gaps between it — the row-width profile dips
sharply between one ingredient and the next, and the deepest dips are the seams.

**The ice cream** (`scripts/build-icecream.py`, `assets/source/ice-cream1.zip`,
also 30 PNGs) is a plain 360° turntable — a scoop in a cone that rotates in
place and doesn't come apart, so there's no layer geometry to measure, just a
straight scrub through the frames. It crops to 8% of the source area.

Both `*Story.tsx` components pin their stage with ScrollTrigger and scrub it,
with a **hold** at the point that matters — the burger's while its ingredients
are labelled, the ice cream's on the last frame so its closing line can be read.
A pose that never stops moving cannot be read. Neighbouring frames are
cross-dissolved, which is what turns 30 stills into continuous motion — and it
has to be a linear dissolve (`lighter`), because these frames carry alpha and
painting one over the other leaves two subjects on screen.

Every frame of both sequences is preloaded and decoded before its scrub is
allowed to start, so nothing is ever seen half-loaded — each has its own
`useFrameLoader` instance and its own loading bar. `prefers-reduced-motion`
skips all of it: the burger renders two stills (closed, apart), the ice cream
renders two stills of its own (front, the opposite side).

## Rules worth keeping

- **Nothing in the scroll-driven path may read or write layout.** Geometry is
  measured once per resize into a plain object; the loop writes only `opacity`
  and `transform`, plus the canvas blit. Measured: 28 layouts across a 91-step
  scrub, 0.42 ms of script per frame.
- Don't position an element with a CSS `transform` that GSAP also tweens — the
  tween overwrites it. Centre with flex instead.
- **Never let two tweens own the same property.** A one-shot entrance and a
  scroll-driven exit on the same `opacity` means reversing the scrub restores the
  entrance's recorded values, and the element never comes back. One timeline,
  `fromTo` everywhere, and put entrances on a child element.
- **No `animation-timeline: view()` on content that must be visible.** With
  `animation-fill-mode: both` it pins the element at opacity 0 until the browser
  decides it entered — and jumping to a section via an anchor never advances it,
  so the whole menu renders blank.
- A non-square image under `border-radius: 50%` is an ellipse. The crest is cut
  to a transparent square by `scripts/build-logo.py`.
- Anything GSAP fades in must start hidden in CSS, or it flashes at full
  strength before GSAP runs.
- `ffmpeg`'s AVIF muxer drops the alpha plane; frames go through `avifenc`.
- After rebuilding frames, restart the dev server — Vite serves empty bodies for
  files whose directory was deleted and recreated underneath it.

## Content

Business facts, both translation tables and the menu live in `src/data/`. The
five ingredient labels are matched to what the footage actually shows: this
burger has no pickle or sauce layer and its cheddar never separates from the
patty, so labels for those would point at nothing.

## Verified

Headless Chrome over CDP (no browser MCP tooling in this environment): scroll
forward through both sections and back, more than once, confirms both
headlines and both closing titles return to full opacity every time — a
one-shot entrance and a scroll-driven exit fighting over the same `opacity`
was a real bug here once, see "Rules worth keeping". 31 layouts across a
141-step scrub through both pinned sections combined (was 28 across 91 through
the burger alone) — the ice cream section adds effectively no layout cost of
its own. Both loading bars independently track real fetch progress under a
throttled connection. Reduced motion renders four stills total, no canvas, no
pin. Desktop 1440 and mobile 390 both checked.
